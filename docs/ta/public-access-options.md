# 多人体验与公开投票方案建议

> 目标：让很多投票者不需要逐个加入体验成员，也能看到或体验小程序。
> 结论先行：**正式发布小程序**最适合作为主方案；如果时间来不及，**H5 镜像 + 小程序二维码 + 演示视频**是最稳的兜底。

## 1. 四种方案对比

| 方案 | 多少人可用 | 需要什么 | 优点 | 限制 |
|---|---:|---|---|---|
| A. 正式发布小程序 | 无人数限制 | 小程序备案、类目、隐私指引、代码审核、管理员扫码发布 | 微信扫码即可用，最符合“小程序作业” | 备案/审核需要时间；课件公开需要老师授权 |
| B. H5 网页镜像 | 无人数限制 | 公网静态托管、域名/HTTPS、课件授权 | 投票网站可直接点开，不依赖微信 | 不是小程序本体；内容需同步；公开课件需授权 |
| C. 体验版 | 个人主体 15 人；非个人认证后最多 90 人，未认证/未发布更少 | 把每个体验者加为体验成员 | 不需要公开审核 | 不能给大量投票者使用；管理成本高 |
| D. 视频/截图 | 无人数限制 | 录屏、截图、投票页展示 | 无技术门槛、无版权外的运行风险 | 不能交互，只能“看” |

## 2. 推荐组合

### 首选：A + 二维码

1. 完成小程序备案、类目、隐私保护指引。
2. 上传代码，提交审核，发布正式版。
3. 在投票网站放：
   - 小程序码（微信扫码打开）
   - 3 张核心截图
   - 一句“微信扫码体验完整小程序”
4. 投票网站本身负责投票；小程序不收集投票者信息。

适合：投票周期足够，能完成备案/审核，老师同意公开 PPT。

### 兜底：B + A 的二维码 + D

如果备案/审核来不及：

1. 把已有 H5 网页镜像部署到公网（投票网站直接链接）。
2. 同时放小程序码，能扫码的人体验完整小程序。
3. 再放 60–90 秒演示视频，保证所有人至少能看到交互。

适合：投票马上开始，或部分投票者不用微信。

### 不建议：C

体验版只适合助教、老师和少量测试同学；个人主体只有 15 个体验成员，非个人认证后一般最多 90 个，无法覆盖“很多人投票”。

## 3. 公开投票前必须确认

- 老师是否同意 PPT 页面用于**公网**小程序/H5/投票页，而不仅是课堂。
- PPT 内第三方图片、人物肖像、设备照片是否有授权。
- 是否需要在页面加版权说明、水印、课程名称、主讲姓名。
- 投票结束后是否下线公开版本。
- 投票网站是否允许放 H5 链接/小程序码；是否需要移动端适配。
- 小程序主体是个人还是学校/学院；这决定类目和备案材料。

## 4. 时间建议

- 今天：确认主体、类目、备案材料；向老师发书面授权确认。
- 本周：提交备案；同时准备隐私指引和审核截图。
- 备案通过后：上传代码 → 提交审核 → 发布 → 生成小程序码。
- 投票开始前：在投票页放 H5/二维码/视频三件套，做一次手机端和桌面端检查。

## 5. 如果老师只同意课堂使用

不要公开发布 PPT 页面。可选：

1. 只提交 private 仓库 + 体验版给助教/老师；
2. 公网投票页只放**自制示意图、文字摘要和演示视频**，不放课件原页；
3. 把 PPT 原页替换为“课件页码 + 文字导读”，等授权后再补图。

具体问题与授权模板见 [`ta-questions.md`](ta-questions.md)。

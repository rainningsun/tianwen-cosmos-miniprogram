# 助教确认问题清单

> 用途：在提交前确认作业范围、访问方式、评分重点和内容边界。
> 建议先问“最需要确认的 10 个”，其余可按需要补充。

## 一、最需要先确认的 10 个问题

| # | 问题 | 为什么需要确认 | 我的建议/当前做法 |
|---:|---|---|---|
| 1 | 本次作业最终需要提交什么：GitHub 私有仓库链接、体验版小程序、PDF 报告、演示视频，还是现场演示？ | 决定我最后打包和准备的材料 | 目前有私有仓库 + PDF 展示文件；体验版尚未上传 |
| 2 | 如果仓库是 private，助教希望怎样访问：加 GitHub collaborator、发 zip，还是只看 PDF/视频？ | 避免助教无法打开仓库 | 可提供 GitHub 用户名后邀请；也可导出 zip |
| 3 | 微信小程序需要助教/老师真机体验吗？如果需要，是否可以把助教的微信号加为体验成员？ | 体验版需要成员权限，不能直接公开 | 正式 AppID 已配置；可加体验成员，不提供密码 |
| 4 | 第六讲尚未提供课件，本次作业是否可以先以“5 讲 + 第六讲待更新占位”提交？ | 决定是否需要等第六讲完成再交 | 当前保持占位，不编造内容 |
| 5 | 评分更看重哪一部分：内容完整、信息架构、视觉交互、代码质量、课程理解，还是创新模块？有没有评分表？ | 决定最后时间投入方向 | 当前重点做了信息架构、索引和探索模块 |
| 6 | 新增的五个模块（概念词典、人物/装置、宇宙尺度、双时间线、未解之谜）是必做、加分，还是可选？ | 决定是否需要继续扩展或收缩 | 当前已完成五个模块的基础版本 |
| 7 | 人物/装置的“课外补充”生平是否允许？是否需要逐条标注来源？ | 涉及内容准确性和学术规范 | 当前统一标“课外补充”，不混入课件原文 |
| 8 | 是否需要说明 AI 辅助（内容整理、代码、文档）？课程对 AI 使用的边界是什么？ | 避免学术规范问题 | 可以在报告中单独写“AI 辅助说明” |
| 9 | 投票网站需要很多人体验小程序，具体应采用哪种公开方式：正式发布、体验版，还是 H5/视频？ | 体验版有人数上限，正式发布才能让公众直接使用 | 正式发布无人数限制；体验版个人主体仅 15 人、非个人一般 90 人 |
| 10 | 老师是否书面同意把课件 PPT 页面直接用于小程序、H5 和公开投票页？ | 这属于对课件的复制与公开传播，不仅是课堂使用 | 未确认前保持 private，不公开课件页面 |

## 二、公开投票与多人体验（新增，优先确认）

1. 最终投票页面是公网、校内网，还是课程平台？预计有多少人参与？
2. 投票是否必须通过微信完成？参与者是否都能使用微信扫码？
3. 课程是否允许把小程序**正式发布上线**（需要备案、审核、隐私指引），还是只能使用体验版/开发者工具演示？
4. 如果正式发布，小程序主体、备案和认证由谁提供？个人主体还是学校/学院主体？
5. 投票期间是否需要收集投票者信息？如果需要，由投票网站收集，还是小程序也要收集？当前小程序不收集个人信息。
6. 是否接受把现有 **H5 网页镜像**作为投票入口，小程序二维码作为完整体验入口？
7. 如果无法正式发布，是否可以接受“投票页展示演示视频 + 截图 + 私密体验版”，而不是让所有人直接打开小程序？
8. 投票结束后，是否需要下线或删除公开版本？

## 三、课件授权（新增，优先确认）

1. 老师是否同意把课程 PPT 的页面图直接放入小程序，并在公网投票页/演示视频中展示？
2. 授权范围是否包括：复制、裁剪/压缩、改作页面图、公网访问、投票展示、H5 镜像、演示视频？
3. 是否要求署名、版权页、水印或“仅限课程学习”的提示？当前每页保留课件页码和版权说明。
4. PPT 中的第三方图片、人物肖像、望远镜/装置照片是否也获得授权？如果没有，是否需要替换或删除？
5. 授权是否有期限和使用范围？课程结束后是否需要下架或删除公开版本？
6. 如果老师只同意课堂/校内使用，是否可以用 private 仓库 + 体验版 + 不公开 PPT 的视频完成作业？
7. 是否需要把老师的授权记录（邮件/微信文字）附在作业提交材料中？

## 四、提交与访问

1. 作业截止时间是哪一天？是否有阶段性检查或演示时间？
2. 提交物是否需要一个固定的封面/模板/学号姓名格式？
3. 是否需要提交小程序的体验版二维码？二维码有效期和体验成员如何管理？
4. 如果使用 private 仓库，是否接受 GitHub 邀请？助教的 GitHub 用户名是什么？
5. 是否需要提交 zip 源码包？zip 中是否需要包含 `docs/` 和截图？
6. 是否需要提交演示视频？如果需要，时长和内容范围有要求吗？
7. 是否需要现场演示？现场是否有网络、微信开发者工具和正式 AppID 环境？

## 五、评分与范围

8. 是否有明确的评分表或各项权重？
9. “课程内容整理”和“小程序功能实现”哪一项权重更高？
10. 5 讲内容是否足够？是否要求第六讲必须完成？
11. 50 张原页（每讲 10 张）数量是否合适？需要增加还是减少？
12. 6 篇专题、39 个概念、30 位人物、6 个装置、6 条思想链的规模是否合适？
13. 五个新模块是否需要全部保留？有没有建议删减的模块？
14. 是否需要加入作业/测验/学习进度等功能？（当前版本已移除旧的作业模块）
15. 是否允许使用课外补充内容（人物生平、尺度数字）？比例上限是多少？

## 六、内容与准确性

16. 人物/装置生平的“课外补充”标注方式是否清楚？是否需要列出参考来源或参考文献？
17. 宇宙尺度中标注为“课外补充”的 5 个数字是否保留：地月距离、太阳系边界、银河系直径、仙女座距离、宇宙学尺度？
18. 课件内部矛盾（第 3 讲 p.20 的 137/138 亿年、83%+23%+4%）按原文保留并注明，是否符合要求？
19. 第六讲接入后，是否必须同时进入“主线、索引、探索”所有栏目，还是只需进入相关栏目？
20. 人物/装置图片是否必须？如果必须，课程能否提供有授权的统一素材？
21. 课件原页图片的使用范围是否仅限课堂作业？是否需要在页脚加版权说明或水印？

## 七、发布、备案与版权

22. 本次作业是否要求小程序公开上线？还是体验版/开发者工具演示即可？
23. 如果公开上线，是否需要完成小程序备案、微信认证和隐私保护指引？
24. 小程序名称“天问·宇宙之美”已确认可用；是否需要与课程/学校官方名称、署名保持一致？
25. 课程课件图片、人物肖像、装置照片的版权边界是什么？哪些可以放入 private 仓库，哪些不可以？
26. 作业展示文件（PDF/截图）是否可以包含课件原页截图？

## 八、技术与代码

27. 是否接受原生小程序、无后端、无 npm 依赖、无外部 CDN 的实现？
28. 是否需要后端、登录、数据库或云开发？当前版本没有这些。
29. 代码质量扫描中“图片/音频总量 200K”是建议项未通过；作业是否要求全绿？如果要求，是否允许使用云存储/CDN？
30. 是否需要单元测试、构建脚本、部署文档或接口文档？当前提供静态校验和页面逻辑冒烟测试。
31. 是否需要提供正式 AppID、体验版或测试账号？当前正式 AppID 已配置，但未上传体验版。
32. 是否需要在报告中说明项目结构、数据来源和同步/更新方式？

> 3. 第六讲尚未提供课件，当前“5 讲 + 待更新占位”是否可以先行提交？

> 7. 最终投票需要很多人体验小程序，应该采用正式发布、体验版，还是 H5/视频？如果正式发布，备案和主体怎么处理？
> 8. 老师是否同意把课程 PPT 页面用于小程序、H5 和公开投票页？是否需要书面授权/署名/水印？

## 十、给老师的课件授权确认模板

> 老师您好，我是《天问：宇宙之美》课程的学生。我正在把课程内容做成一个微信小程序作业，最终可能需要在课程展示网站上公开投票。想向您确认课件使用授权：
>
> 1. 是否同意我将课程 PPT 的页面图用于小程序、H5 镜像和投票页面的截图/演示视频？
> 2. 使用范围是否限于本课程作业与展示，不作商业销售，不向第三方再授权？
> 3. 是否需要在页面保留课程名称、主讲姓名、PDF 页码和版权说明？是否需要加水印？
> 4. PPT 中的第三方图片、人物肖像、望远镜/装置照片是否也在授权范围内？如果没有，我会替换或删除。
> 5. 课程结束后，是否需要下架公开版本或删除相关页面？
> 6. 如果最终需要公开投票，能否用邮件或微信文字确认上述范围？
>
> 谢谢老师！

## 十一、建议的确认顺序

1. 先确认 **提交材料 + 访问方式 + 截止时间**（决定能否被看到）。
2. 再确认 **第六讲是否必须完成 + 评分重点**（决定是否继续扩展）。
3. 再确认 **内容边界 + 版权 + AI 规范**（决定文档怎么写）。
4. 最后确认 **技术细节 + 体验版 + 备案**（决定是否上线）。
